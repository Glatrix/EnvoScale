# Golden tests

An input file and its exact expected output, side by side. A test passes when the tool's
output is byte-identical to the expected file (after normalizing CRLF to LF).

| Folder | Tool | Input → expected |
|---|---|---|
| `lexer/` | `envoc0 lex` | `name.envo` → `name.tokens` |

Planned: parser AST dumps (M1), EIR (M2), assembly and diagnostics (M3).

## Token dump format

```
<line>:<col> <n|s|j> <class> <text>
```

- `n` = newline before the token, `s` = whitespace or comment before it (no newline),
  `j` = joint with the previous token ([lex.flags.*]).
- `class` is `kw`, `punct`, `ident`, `int`, `float`, `char`, `string` or `eof`.
- For `kw` and `punct`, `text` comes from the compiler's kind table, so a wrong
  spelling-to-kind mapping shows up as a diff. For the rest it is the source text.

Expected files are **never** generated by the tool under test. The initial lexer
expectations were produced from the spec by an independent reference model (a separate
implementation outside the repository, written from `docs/spec/01-lexical.md`) and then
reviewed line by line. When the spec changes, update the expected files by hand and
explain why in the commit.

Inputs in `lexer/` are marked `-text` in `.gitattributes` because some depend on exact
bytes (a BOM, CRLF line endings).
